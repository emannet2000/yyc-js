1. Introduction

YYC Brokers is a delivery workspace for trucking brokers, the businesses that need goods moved (called store owners here), and the drivers who move them. The app is a React web application backed by a Node.js API and an SQLite database. Drivers can also use a companion Android app for background location sharing.

The app keeps three commitments separate, because they are made by different people at different times:

  • The store agrees to the service and the customer price. It accepts a quotation for a specific version of the delivery.
  • The broker arranges the work. It prices the job, selects a driver, and sends the offer.
  • The driver accepts responsibility for the cargo. Acceptance, pickup and delivery each record who acted and when.

Every step is recorded in the delivery's activity history, and the app checks rules on the server, not only in the screen, so a button cannot bypass an outstanding problem.

Not a payment processor. The app records invoices, payments, refunds and driver payouts as a ledger. It does not charge cards or move money between bank accounts. Reconcile ledger entries against your real payment process.

3. Getting started (developers and evaluators)

Use this path to run the app on your own computer with sample data. It is not a production setup.

Requirements

  • Node.js 22.13 or newer, and npm. Node 22 may print an experimental SQLite warning; that is expected.
  • A terminal opened in the project folder.

Steps

1

Install dependencies.

npm ci
2

Load sample accounts into the local database (development only).

npm run seed

Creates a broker, a store and a driver. Sample credentials are listed in scripts/seed.js. Change or delete them before any real use.

3

Start the API and the development frontend together.

npm run dev

The API runs on http://127.0.0.1:3000. Vite shows its own address; open the Vite URL at /react/.

4

Sign in with a sample account, or register a new store or driver. Drivers and trucks need broker approval before they can accept work.

Database location. By default the database is data/yyc.sqlite. Set DATABASE_PATH to use another file. Parent folders and an empty schema are created automatically. Tests never touch the workspace database.

Running the checks

npm test              # unit, integration and DOM tests
npm run lint          # ESLint
npm run format:check  # Prettier
npm run build         # type-check and production build
npm run test:browser  # Playwright acceptance (needs: npx playwright install --with-deps chromium)

4. Deploying and creating the first broker account

A new production workspace has no accounts. Public registration cannot create a broker, and there are no default passwords. The first broker is created through a one-time setup token.

Operator steps (server)

1

Copy .env.example to .env. Set PUBLIC_ORIGIN to your HTTPS address, keep NODE_ENV=production and COOKIE_SECURE=true, and point DATABASE_PATH and BACKUP_DIRECTORY at persistent storage.

2

Build and issue a setup token.

npm ci
npm run build
node --env-file=.env server/setup.js

The token expires after 30 minutes, is stored only as a hash, and is consumed when the first broker is created.

3

Start the service under a process supervisor. Put HTTPS in front of it with a reverse proxy that forwards to 127.0.0.1:3000, and preserve the original Host header.

npm run start:configured

First-broker steps (browser)

4

Open the login page and choose Set up broker account.

5

Enter the setup token, then your broker name, contact phone, email and password.

Setup closes permanently once the first broker exists, even if that account is later disabled. Keep the setup token private and do not send it through chat.

Startup safety checks

The server refuses to start with an invalid production origin, insecure cookies, an ephemeral database, or invalid backup settings. This is deliberate; read the error message and correct the .env file.

Routing and tracking providers (optional)

Road distance, driving time and ETA need a routing provider. Configure either an OpenRouteService key (ORS_API_KEY, with ORS_PROFILE=driving-hgv for a truck profile) or your own OSRM-compatible and Nominatim-compatible endpoints (ROUTING_URL, GEOCODING_URL). Keep provider credentials on the server; they are never placed in frontend or Android code. Without a provider, pickup-window scheduling still works, but road ETAs are unavailable.

5. Signing in, registering and recovering access

Sign in

Open the login page, enter your email and password, and choose Log in. Sessions end on logout, when a password changes, or when an account is disabled.

Register

AccountWhat to enterWhat happens next
StoreBusiness name, contact phone, email, password; store delivery address and receiving contactCan request deliveries immediately.
DriverFull name, phone, email, password; truck make/model, plate or unit reference, truck type (Box truck or Dry van), payload (kg), pallet capacity, service area, liftgate yes/noWaits for broker approval of the driver and the truck before accepting jobs.
BrokerNot available publiclyCreated by setup or by an existing broker in Accounts.

Public registration is rate-limited per connection address (20 attempts per 15 minutes). Duplicate emails and truck plates are rejected.

Forgotten password

  • Forgot password? asks for a reset. If the operator has configured email delivery (RESET_DELIVERY_URL, HTTPS only), a reset link is sent. Reset links expire after a short window and work once.
  • If no email delivery is configured, ask a broker. A broker can issue a recovery link after verifying your identity through a trusted private channel.

Broker-issued recovery link

1

In Accounts, open the account, enter a recovery verification reason (the page reminds you to verify the account holder first), and choose Create password reset link.

2

Share the link through a verified private channel. It expires after 30 minutes and works only once.

3

The person opens Recover your account and sets a new password. This signs out every session and invalidates all recovery links.

Why the link is safe to open once: the token lives in the URL fragment, which the page removes from browser history after reading it. Only a hash is stored on the server.

If the only broker loses access

An operator provisions another broker with the local command node --env-file=.env server/create-admin.js, using ADMIN_EMAIL, ADMIN_PASSWORD (12–128 characters), ADMIN_NAME and ADMIN_PHONE. Then that broker performs verified recovery for the locked-out person.

7. Store owner guide

STORE OWNER Your job is to describe the work accurately, review the price, and tell the broker when something needs to change.

7.1 Complete your store profile

Open Store profile and keep your business name, delivery address and receiving contact current. These values pre-fill future requests and reduce repeated entry.

7.2 Request a delivery

1

Choose Request delivery.

2

Enter the pickup address and the delivery address.

3

Set the pickup date and pickup window (for example Morning or Afternoon). Flexible windows overlap every other window that day.

4

Describe the cargo: goods, weight (kg) and pallet count. Choose the vehicle type (Box truck or Dry van) and list any unloading requirements, such as a liftgate.

5

Enter the pickup contact, the receiving contact, receiving hours, and an optional appointment reference, cargo details and additional instructions.

6

Optionally set a delivery deadline. Deadlines are in Edmonton time.

7

Select Submit delivery request. The delivery appears as Awaiting quote.

7.3 Review and accept the quotation

When the status is Quote ready, open the delivery, check the price against the shipment details, and select Accept quotation. Acceptance applies to the current version only. If the broker corrects the quote later, you must accept the corrected version.

Do not accept a price you disagree with. Submit an owner request instead (see 7.4). Acceptance moves the job forward and lets the broker arrange a driver.

Quotes expire after 48 hours. An expired quote returns to the broker for a new one.

7.4 Owner requests

Use Owner requests on a delivery to ask for changes after the initial request. There are three kinds:

Request typeUse it toTypical result
Quotation reviewQuestion the priceBroker changes the customer price; you must accept again.
Destination or cargo changeChange the address, weight or pallet countBroker approves and the work gets a fresh quotation, or declines with an explanation.
CancellationStop the deliveryBefore pickup, the job closes. After pickup, cargo is returned rather than discarded.
  • Only one request can be waiting at a time. An urgent cancellation can replace an older pending request; both stay in the history.
  • Until the broker responds, the current instructions stay in force. Submitting a request does not change the driver's instructions.
  • You can withdraw a pending request, with a short explanation.

7.5 Follow your deliveries

  • My deliveries lists everything you have requested, searchable by reference, address, cargo or status.
  • Tracking shows the live location, next-stop ETA and progress for deliveries in transit (see Section 12).
  • Action required lists anything waiting on you, such as a quote to accept or a pending owner request decision.
  • Notifications record changes that affect you. Email delivery requires the operator to configure it; in-app notifications are always kept.

8. Broker guide

BROKER You own the middle of the process: pricing, dispatch, exceptions, accounts and money records.

8.1 Daily routine

  1. Open Work queue (the Action required list) and work from the top. Items are ordered by urgency: open exceptions and owner requests first, then overdue pickups and quotes, then new requests.
  2. Check Approvals for new drivers and trucks.
  3. Check Work board for the flow of deliveries across statuses.
  4. Check Operations for live deliveries, ETAs and reports.

8.2 Approve drivers and trucks

Approvals lists each driver with a badge: Approved when both the driver and truck are approved, or Pending review otherwise. Choose Approve or Reject. An approved driver can be stopped later with Revoke approval.

Approval records your decision. The app does not verify licences, insurance or vehicle inspections. Complete those checks in your own process first.

8.3 Price the job (quotation)

1

Open a delivery with status Awaiting quote. Review cargo, route, schedule and equipment. Clarify ambiguous addresses or cargo figures with the store before pricing.

2

Enter the Customer quote (CAD) and the Driver rate (CAD). Both must be positive amounts in whole cents; fractional cents are rejected.

3

Select Issue quotation. The status becomes Quote ready.

8.4 Correct a quotation

Before pickup, Correct quotation lets you change the amounts. You must give a reason and change at least one amount. The previous quote is archived, any assignment or pending offer is cleared, and the delivery returns to Quote ready. After pickup, corrections are rejected.

8.5 Send a job offer

1

With the status Ready to assign, select Send job offer.

2

Open Review driver availability. Each driver is listed as Available, or with the reasons they are blocked: approval, truck capacity, pallet capacity, liftgate requirement, or a scheduling clash.

3

Choose an approved, suitable driver and send the offer. The status becomes Offered.

Offers expire after one hour if unanswered, which frees the driver's schedule. A sent offer is not a confirmed job until the driver accepts. Withdraw an offer with a reason if you change your mind.

8.6 Reschedule

If the pickup date passes before pickup, the app asks for a new date under Reschedule delivery. Rescheduling requires fresh customer acceptance and clears current driver commitments, so the driver must be offered again.

8.7 Resolve exceptions

When a driver reports an exception (damaged cargo, closed receiving location, unavailable contact, unsafe unloading), it appears as an open issue on the delivery and blocks pickup or delivery progress. Open the delivery, review the reason and evidence, then record a Resolution. The driver can then continue. Record a clear resolution; it is part of the audit trail.

8.8 Approve or decline owner requests

Owner requests appear in your queue. For each one, either:

  • Approve and apply the change. Customer price changes need fresh store acceptance. Shipment changes return the work for a new quotation.
  • Decline with a clear explanation. The current instructions remain in force.

9. Driver guide

DRIVER You accept responsibility for cargo. Read every offer carefully, and only accept a job you can complete.

9.1 Register your truck

Create a driver account and enter your contact details. Then enter your truck: make and model, plate or unit reference, truck type, payload (kg), pallet capacity, service area and whether it has a liftgate. Your broker must approve both you and the truck. Until then, you cannot accept jobs. Keep the truck profile current; any change that affects capacity or equipment needs your broker's review.

9.2 Respond to a job offer

Offers appear under Job offers and in Action required. Each offer shows the route, cargo, schedule, handling requirements and your agreed rate. The customer price is never shown to drivers.

9.3 Collect the cargo

1

After accepting, the status is Assigned. Head to the pickup.

2

When you arrive, select Record arrival. This documents the milestone and starts the location trail.

3

After loading, select Confirm pickup. The status becomes In transit and you are responsible for the load.

Do not confirm pickup for cargo that is not in your truck. If cargo is missing, damaged, incorrectly described or unavailable, report an exception instead. Pickup is blocked while an exception is open, and blocked if you already hold another live load.

9.4 Route and stops

The Route and stops panel lists your origin, pickup, each intermediate stop in order, road distance and driving time (when routing is configured), and the next stop ETA. Work through stops in order. For each stop select Complete next stop once it is done; each stop can have its own receipt and receiving contact. Brokers can edit the stop list until the job is in transit; stores can edit it only while the request is Awaiting quote.

9.5 Deliver and upload proof

Delivery needs all of the following:

  1. All intermediate stops completed.
  2. Arrival recorded at the final destination.
  3. No open exception.
  4. A proof file uploaded after arrival, linked to the current attempt. Accepted types are PNG, JPEG and PDF, up to 2 MiB each. Use Evidence files to add them; up to ten general files are allowed, and a reserved slot is kept for the completion proof.
  5. A receipt reference and the recipient name.

Then select Confirm delivery. The status becomes Delivered. The server stores the evidence reference and its SHA-256 hash, your identity, arrival time and confirmation time.

Proof taken before pickup does not qualify, even when its timestamp looks right. A typed name or filename alone cannot complete delivery. The records document what you submitted; they do not verify the recipient's identity.

9.6 Failed delivery attempts

While the job is In transit, if you cannot complete the drop-off, select Delivery attempt failed and explain what happened. Keep the cargo safe and wait. The broker will arrange either a redelivery or a return, and the screen will say which step is waiting on whom.

9.7 Driver rate proposals

If the broker proposes a new rate for a job you already hold, the screen shows Review the proposed driver rate. Accept the new rate, or keep your existing agreed rate. Your assignment stays in place either way. Until you accept, the old rate applies.

9.8 Payouts and history

Payouts shows only your own allocations and payout records. Delivery history lists your past jobs and their evidence.

10. Changes, returns and handovers

Real operations change. These procedures keep responsibility clear while they do.

10.1 Cancel or return cargo

  • Before pickup: a cancellation closes the job, and any dispatch commitment is released.
  • After pickup: cancellation becomes a return. The broker arranges Arrange cargo return, the delivery enters Returning, and the driver must record arrival at the return location.
  • To finish a return, the driver enters a return receipt reference and the name of the person who received the cargo. The status then becomes Returned.

10.2 Redelivery after a failed attempt

The broker chooses Arrange redelivery and sets a new attempt. The driver keeps the cargo until the new attempt. Completed evidence from the failed attempt stays in the record.

10.3 Driver rate changes

WhenWhat happens
No driver selected yetBroker changes the rate immediately.
Offer or assignment in placeThe new rate is a proposal. The driver must accept it. Declining keeps the agreed rate, and pickup proceeds at that rate.
Customer price changesSeparate path. Needs fresh customer acceptance and releases current dispatch commitments.

Financial histories and proposed driver rates are hidden from store owners.

10.4 Driver handover (broker)

1

On an assigned or in-transit job, choose Arrange driver handover. Pick an approved, suitable replacement driver and enter a reason.

2

The original driver stays assigned, and their tracking stays visible, until the replacement accepts.

3

When the replacement accepts, responsibility moves and the pickup progress, shipment details and accepted customer quote are preserved. An in-transit delivery stays in transit.

4

You must arrange the physical cargo transfer yourself. The app records responsibility; it does not move the goods.

The replacement can decline. The broker can withdraw an offer before it is accepted. Completed trips cannot be handed over.

Do not use a handover to remove a job from someone's screen. Handover should correspond to a real, understood transfer of responsibility.

10.5 Recording an exception

Drivers report an exception from the delivery screen with a short description. Brokers see it at once, and it blocks progress until resolved. Exceptions are recorded, not hidden: resolve them with a clear note. Replacement drivers can accept a rescue handover while an exception is open, but the exception still holds progress until the broker resolves it.

11. Billing, payouts and reports

11.1 Invoicing (broker)

Once a delivery or return is Delivered or Returned, it appears under Action required as "Issue invoice". Select Open invoice form (or choose it in Billing), review the completed job, and issue the customer invoice. Confirmation shows "Invoice issued."

11.2 Recording money movements (broker)

RecordUse it for
Customer paymentMoney received from the store against an invoice
Refund or adjustmentMoney returned, or a correction to the customer's balance
Driver payoutMoney paid to a driver, from their allocated share

Record a transaction only after you have verified it in your bank or payment process, and include a reference that matches that record. Customer billing and driver payouts are separate: a completed delivery does not mean the customer has paid, and a customer payment does not mean the driver was paid.

11.3 Driver payout allocation (broker)

For a job with more than one driver (after a handover), use Driver payout allocation to split the agreed total driver rate. Each driver's share needs a recorded reason. A sole cargo driver receives the whole rate by default. Allocation reductions below amounts already paid need a verified reversal first. Payouts are checked against each driver's balance, and allocation revisions are kept in history.

11.4 Reports (broker)

Reports shows delivery and financial summaries. Apply filters, such as a pickup date range or status, then select Export CSV to download the results for spreadsheet work.

The app does not move money. It is a ledger of what your business has verified. Keep the external records as the source of truth.

12. Live tracking, ETA and recipient links

When a driver is on the road, the app can show where the truck is and when it will reach the next stop.

12.1 What the screens show

  • Location and ETA (delivery drawer): the last shared driver location with its time, and the ETA. If nothing has been shared, the screen says "No location has been shared."
  • Route and stops: road distance, driving time, next-stop ETA, and the itinerary in order.
  • Update ETA (broker): a manual adjustment when you know more than the estimate, for example after a loading delay.
  • Driver sync: whether the driver's device is currently sending updates.

12.2 Limits you should understand

  • ETA is an estimate. It does not model loading time, receiving restrictions or access problems.
  • Browser sharing stops if the phone locks or the browser closes. Stale locations are not presented as live.
  • ETA is recalculated after accepted location updates, at most once per minute, and only when a road provider is configured.

12.3 Recipient tracking link

A broker or the driver can copy a Recipient tracking link. It opens the public YYC delivery tracking page for the receiving party, showing the scheduled pickup or redelivery and progress. Links need the operator's PUBLIC_ORIGIN to be set. Share the link only with the people who should see the delivery.

13. Android companion app

The Android app, YYC Driver, sends GPS updates for one assigned delivery from a foreground service. It keeps running when you lock the screen or close the browser, subject to phone settings. It is a companion: all job actions still happen in the web workspace.

13.1 Pair and run

  1. Sign in on the web workspace as the approved driver and open the assigned, active delivery.
  2. Under Background location sharing, choose Pair Android phone. Note the one-time code before it expires (five minutes).
  3. In YYC Driver, enter the workspace address (HTTPS), the code and a phone name, then tap Pair this phone.
  4. Tap Start background location sharing while the app is open. Grant location (precise is recommended for better ETAs) and notification permissions.
  5. A persistent notification shows the delivery and a Stop sharing action. Closing the browser or locking the screen does not stop it.

13.2 Stopping and disconnecting

  • Stop location sharing pauses the service.
  • Disconnect this phone clears the stored token and asks the server to revoke it.
  • Pairing a new phone revokes the previous one for the same driver and delivery.
  • Completing the delivery, losing the assignment, account disable, password recovery or database restore all revoke the device.
  • Brokers and drivers can revoke a device from the delivery drawer.
Battery and vendor settings can stop tracking. Aggressive battery optimization, a force-stopped app, or a revoked permission will interrupt sharing. If it stops, reopen YYC Driver and press Start. Check the phone's location and battery settings for the app.

The app stores credentials encrypted in Android Keystore, excludes them from device backups, and keeps no password. Build and install instructions are in mobile/android/README.md; the Android build requires the Android SDK and JDK 17.

14. Offline work and sync

Drivers can keep working briefly without a connection. Actions are kept on the device and sent when the connection returns.

  • Offline, a driver can queue arrival, file attachment and delivery confirmation, in that order, after pickup.
  • Evidence files are stored in account-scoped browser storage until they sync. Large files can use up browser storage.
  • Completion stays provisional until the server accepts every queued action.
  • If the broker changes the job before sync, replay stops for review. Newer instructions are never overwritten by an older offline version.
  • The workspace refreshes automatically when connectivity returns, before and after syncing.
  • Drafts (for example, a delivery receipt or recipient name) are kept in memory for the signed-in driver. They do not survive a full page reload, so finish entries before reloading.

15. Operations: backups, recovery and the command line

This section is for the person who runs the server. Run commands from the project folder. Use --env-file=.env on a deployed server so commands target the same database as the running service.

TaskCommand
Create the first broker (one-time token)node --env-file=.env server/setup.js

Recovery drillnpm run recovery:drill
Demo data (development only)npm run seed

15.1 Backups

  • Backups use SQLite's consistent snapshot method, including committed write-ahead log contents, and check integrity and foreign keys.
  • Both source and destination must be correct: commands refuse to overwrite an existing file or the source.
  • Snapshot files are readable only by the service account (mode 0600). Keep them on persistent, access-controlled storage, and copy them off-host.

15.2 Restore

Restore validates the snapshot and keeps accounts, password hashes, shipments, booking keys and audit records. It clears sessions and password recovery tokens, so everyone signs in again. To switch the service, stop it, then start it against the restored file:

DATABASE_PATH=data/yyc-restored.sqlite npm start
Practise a restore before you need one. Run a recovery drill on a copy and confirm you can sign in and see recent deliveries.

15.3 Account management (broker)

  • Use Accounts to view stores, drivers and other brokers.
  • Disabling an account requires a reason. It revokes sessions and reset tokens, withdraws unaccepted offers, and records an audit event. Accepted jobs stay assigned for review.
  • You cannot disable your own account, and the last active broker is protected.
  • To add a broker, choose Add broker account, enter the full name, email, contact phone and a password (entered twice), then select Create broker account. Every broker account has the full broker role.
